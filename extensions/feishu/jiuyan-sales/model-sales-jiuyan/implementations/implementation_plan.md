# 未来 12 个月总销量预测模型设计方案

## 数据概况

| 维度         | 数值                                                 |
| ------------ | ---------------------------------------------------- |
| 数据时间跨度 | 2021-03 → 2026-02（约 60 个月）                      |
| 总记录数     | 约 1500 万条                                         |
| 产品分类     | 4（鱼钩、线组、加长子线、无结子线）                  |
| 销售渠道     | 12（主力：头条放心购、淘宝天猫、拼多多、快手、京东） |
| SKU 数       | 4,097                                                |
| 门店数       | 1,247                                                |

### 已发现的数据特征

1. **强季节性**：钓鱼用品呈明显季节波动，7-10 月为旺季（月销 ~85-95 万），1-2 月为淡季（月销 ~15-25 万），峰谷比约 3-4x
2. **增长趋势**：2021-2024 快速增长（月销从 ~3 万增至 ~90 万），2025 年趋于稳定
3. **品类差异**：鱼钩和线组占近 93% 销量，加长子线和无结子线增长迅猛但基数小
4. **渠道结构变化**：头条放心购占比约 55%，拼多多/淘宝天猫持续增长，阿里巴巴/微信视频号体量小但增速快
5. **春节效应**：2026-02 数据完整，销量低（14.6 万 vs 2025-02 的 24.2 万）是因为春节休假，属正常季节波动

---

## 预测目标

- **预测对象**：2026-03 ~ 2027-02，共 12 个月的 **SKU 级净销量**（`SUM(净销量)`）
- **预测粒度**：SKU × 月度
- **总规模**：约 4,000 个 SKU，每个预测 12 期，总计约 48,000 条预测记录
- **输出**：SKU 级预测值，可聚合得到品类、渠道及全公司总量

---

## 模型架构设计

### 方案：全局预测模型 (Global Forecasting Model)

面对 4,000+ 个 SKU，单独为每个 SKU 训练模型（如 SARIMA 或 Prophet）效率极低且难以处理新 SKU/短序列问题。**推荐使用全局机器学习模型（LightGBM）**。

#### 核心思路

将所有 SKU 的历史数据“堆叠”在一起，训练一个统一的模型。模型通过 SKU 的**静态特征**（如品类、属性）和**动态特征**（如历史销量、季节性）来学习不同 SKU 的销售模式。

#### 核心特征工程

1. **滞后特征 (Lag Features)**：该 SKU 在 $t-1, t-2, \dots, t-12$ 月的销量。
2. **滚动统计 (Rolling Statistics)**：过去 3/6/12 个月的均值、最大值、方差。
3. **商品静态属性**：来自 `dim_sku` 的 `product_category`, `spec_length`, `spec_size`, `price_tier`。
4. **时间/节日特征**：
   - 月份（1-12）
   - **农历春节距离**（相对于 1 月 1 日的天数偏移），用于捕获 2026-02 类休假效应。
5. **编码特征**：对商品编码进行频率编码或 Target Encoding。

#### 技术选型：LightGBM (Recursive Forecasting)

由于要预测 12 个月，采用 **递归预测 (Recursive)** 或 **直接预测 (Direct)**：

- **递归预测**：先预第 1 个月，将其预测值作为第 2 个月的滞后特征，循环 12 次。
- **优点**：能够学习到 SKU 之间的共性规律，对数据较少的新 SKU 有很强的泛用性（冷启动能力）。

## 数据预处理

### Step 1：数据聚合视图

```sql
-- SKU 级月度汇总 (核心训练数据)
CREATE VIEW v_monthly_sku_sales AS
SELECT
    substr(日期, 1, 7) AS year_month,
    商品编码 AS sku_code,
    SUM(净销量) AS monthly_qty,
    COUNT(DISTINCT 店铺) AS active_stores_per_sku
FROM sales
GROUP BY substr(日期, 1, 7), 商品编码;

-- 关联 SKU 维度信息
CREATE VIEW v_training_base AS
SELECT
    s.*,
    d.product_category,
    d.spec_length,
    d.spec_size,
    d.last_base_price
FROM v_monthly_sku_sales s
LEFT JOIN dim_sku d ON s.sku_code = d.sku_code;
```

### Step 2：数据清洗

1. **首月处理**：2021-03（仅 1,780 销量，业务刚起步）作为热身数据，不参与训练
2. **春节效应建模**：春节期间休假导致销量显著下降（如 2026-02 仅 14.6 万），需在模型中加入农历春节日期作为特征变量
3. **异常值检测**：用 IQR 或 Z-score 检查月度数据中是否有异常跳变
4. **平稳性检验**：ADF 检验，判断是否需要差分

## 评估策略

### 回测验证 (Backtesting)

使用 **时序交叉验证**，模拟真实预测场景：

| 折数   | 训练集            | 验证集            |
| ------ | ----------------- | ----------------- |
| Fold 1 | 2021-04 ~ 2024-02 | 2024-03 ~ 2025-02 |
| Fold 2 | 2021-04 ~ 2024-08 | 2024-09 ~ 2025-08 |
| Fold 3 | 2021-04 ~ 2025-02 | 2025-03 ~ 2026-02 |

### 评估指标

| 指标                          | 用途                                               |
| ----------------------------- | -------------------------------------------------- |
| **WAPE** (加权绝对百分比误差) | 适用于 SKU 级，权重按销量大小分布                  |
| **MAE / RMSE**                | 常规误差指标                                       |
| **Aggregated MAPE**           | 将 SKU 预测汇总到品类/总量层级后，考察与真实的偏差 |

## 已确定的设计方案

- **预测粒度**：**SKU 级 (Bottom-up)**。模型直接产出 4,000+ 个 SKU 的月度预测。
- **品类/总量汇总**：通过对 SKU 预测值进行简单求和获得各层级（品类、渠道、全公司）的总体预测。
- **金额预测**：本次**不涉及**金额预测，仅关注销量。
- **数据处理**：2026-02 销量低点按原始数据处理，由“农历春节偏移”特征解释。

## Verification Plan

### Automated Tests

1. 回测验证：在 Fold 3（训练到 2025-02，验证 2025-03 ~ 2026-02）上比较预测值与真实值
   - 运行命令：`python forecasting/evaluate.py --fold 3`
   - 目标：总销量 MAPE < 15%

2. 单模型 sanity check：确保 Prophet / SARIMA / LightGBM 各自产出 12 个月预测值且无 NaN
   - 运行命令：`python forecasting/train.py --validate`

### Manual Verification

- 肉眼检查预测曲线是否符合季节规律（3-4 月上升，7-10 月高峰，12-2 月低谷）
- 检查预测值数量级是否合理（月销量在 20 万 ~ 100 万区间）
